📋 Detailed RAG Workflow:

  1. Document Ingestion: PDF files are uploaded to the ./data folder and processed by the ChromaDB system
  2. Text Chunking: Documents are split into overlapping chunks (1000 chars, 200 char overlap) using RecursiveCharacterTextSplitter
  3. Embedding: Each chunk is embedded using Nomic Embed (free, open-source) → 384-dimensional vectors
  4. Vector Storage: Embeddings are stored in ChromaDB with metadata (source, chunk_index, timestamp)
  5. Query Processing: User query is embedded using the same Nomic Embed model
  6. Semantic Search: ChromaDB performs cosine similarity search to find top-K most relevant chunks
  7. Context Construction: Retrieved chunks are formatted as context for the LLM
  8. LLM Generation: Groq API (OpenGPT 1.20B) generates an informed response using the context
  9. Response Display: Result shows retrieved chunks with similarity scores and AI-generated answer
